LLaMA-Factory Trainer

A Runpod Serverless worker that runs headless LlamaFactory v0.9.5. Send an official training YAML (or a few form fields) plus an alpaca / sharegpt dataset; get a LoRA / QLoRA adapter (adapter_model.safetensors + adapter_config.json).

GitHub Runpod Hub README llms.txt openapi.yaml

What you send / what you get

  • Send config_yaml / config_url, or flat fields, plus dataset_url, dataset_inline, or a named dataset.
  • Get an adapter on your network volume, a Hugging Face repo, or an archive / S3 upload.
  • Stages: SFT, DPO, ORPO and SimPO (stage: dpo + pref_loss), KTO. Methods: QLoRA 4/8-bit, 16-bit LoRA, freeze, full.
  • Default: Qwen/Qwen3-4B-Instruct-2507 (Apache-2.0, not gated, bf16) QLoRA 4-bit on a 24 GB GPU (RTX 4090).

Not the same as

  • Unsloth Fine-Tuning Worker — faster plain SFT with Unsloth kernels, JSON fields only, no YAML and no DPO/ORPO/KTO. This listing keeps official LlamaFactory YAML first-class and leaves use_unsloth false.

Example job

{
  "input": {
    "dataset": "tiny_sft",
    "stage": "sft",
    "finetuning_type": "lora",
    "quantization_bit": 4,
    "max_steps": 5,
    "max_samples": 16,
    "cutoff_len": 512,
    "lora_rank": 8
  }
}

Worker code is MIT. Upstream LlamaFactory is Apache-2.0, pinned at v0.9.5. The default Qwen3-4B-Instruct-2507 weights are Apache-2.0; any other base model keeps its own license. No Gradio / LLaMA Board. Weights are not baked into the image.
